# 演示架构

## 架构目标

在纯前端环境中，完整演示“风险预警 -> 监控告警 -> 固证与策略建议”的业务闭环。

## 当前技术栈

- React + TypeScript + Vite
- Material UI（统一视觉风格）
- 本地 mock 数据（不依赖后端服务）
- Vite 中间层 Agent 网关（/agent -> Ollama）

## 目标态架构（宣传口径）

- 多模态 AI 识别层：负责文本、图像、音视频侵权信号提取。
- 法律规则引擎层：负责规则计算、依据映射、可解释输出。
- 监控与固证平台层：负责巡检、告警、证据存证与文书生成。
- 企业集成层：负责与法务工单、CRM、风控系统联动。

## 前端模块划分

### 1. Prophet 模块（发布前风险预警）

职责：

- 选择创意案例（海报文案、短视频标题、谐音梗）
- 渲染四色风险结果
- 展示置信度、法律依据、参考判例、建议动作

### 2. EagleEye 模块（全网监控告警）

职责：

- 展示监控对象列表
- 展示疑似侵权告警时间线
- 支持“模拟触发告警”交互，便于现场演示

### 3. JudgeAssistant 模块（固证与维权策略）

职责：

- 展示证据包结构（截图、链接、时间戳、哈希）
- 展示投诉文书生成状态
- 展示策略建议对比（快速下架 vs 诉讼准备）

## 数据组织约定

- 所有业务数据集中在 src/data 下。
- 案例数据遵循统一 schema，便于未来接入真实 API。
- 风险输出固定字段：
  - color: red | orange | yellow | green
  - confidence: 0.0 - 1.0
  - legalBasis: string[]
  - precedents: string[]
  - recommendation: string

## 演示交互原则

- 任意模式切换都要有明显视觉反馈。
- 关键动作（例如“模拟告警”“生成证据包”）要有状态变化和结果提示。
- 页面默认中文文案，尽量减少评委理解成本。

## 后续扩展（赛后）

- 将 mock 数据替换为 API 数据源。
- 引入账号体系和任务历史。
- 增加规则引擎配置界面，支持法务团队维护阈值和判例映射。
